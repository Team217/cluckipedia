# Simulation Strategy

Simulation lets the whole team write and test code before the robot exists, and lets students work
from home. This page explains what we simulate, with which tools, and why.

## The layers

| Layer | Tool | What it gives you |
|---|---|---|
| **Motor controller** | Phoenix 6 simulation (`TalonFXSimState`, `CANcoderSimState`, `Pigeon2SimState`) | The real TalonFX firmware behavior: Motion Magic, PID, limits, current limits |
| **Mechanism physics** | WPILib physics sims (`DCMotorSim`, `FlywheelSim`, `SingleJointedArmSim`, `ElevatorSim`) | How the mechanism responds to voltage: inertia, gravity, gearing |
| **Drivetrain** | CTRE's swerve simulation (generated by Tuner X) | A drivable swerve robot with odometry |
| **Vision** | PhotonVision `VisionSystemSim` | Simulated AprilTag detections from the simulated pose |
| **Game pieces / field** | Custom code (see below) | Intake/score interactions, for testing autos |
| **Visualization** | AdvantageScope | 2D/3D field, CAD robot models, mechanism views |

The [Mechanism Simulation](mechanisms.md) page shows how the first two layers connect.

## What about MapleSim?

The 2026 code uses **maple-sim** (the "ironmaple" package vendored inside `swervelib/`) for
swerve-drive physics, collisions with field elements, and game-piece interactions. Here's where
it stands as of late 2026:

- maple-sim is **not archived or officially deprecated**. It shipped a 2026 (REBUILT) release,
  but it was labeled **beta**. The maintainers warned of instability and API changes, and some
  2026 versions had crash bugs.
- At least one other team reported **disabling it when moving to 2027** because there was no 2027
  release yet.
- Our copy is a **vendored fork inside YAGSL**. Since we're dropping YAGSL, we'd lose it anyway.

**Recommendation: don't build our 2027+ simulation on maple-sim.** Use the stack below, which is
fully supported by WPILib and CTRE every season:

1. **Drivetrain:** CTRE's generated swerve code, which includes a `SimSwerveDrivetrain` that
   simulates the modules and Pigeon with Phoenix 6 sim. Pair it with the
   [AdvantageKit TalonFX swerve template](https://docs.advantagekit.org/getting-started/template-projects/talonfx-swerve-template/) ([offline](../../reference-materials/offline/advantagekit-reference.md#talonfx-swerve-template))
   for logging and replay. CTRE describes its sim as an idealized drivetrain (no collisions, no
   wheel slip), which is good enough for developing and testing autos.
2. **Mechanisms:** WPILib physics sims driving Phoenix 6 sim state (the `ArmIOSim` pattern).
3. **Game pieces:** a small team-owned utility that tracks game piece positions as `Pose3d`s and
   checks simple "is it inside the intake zone?" and projectile-arc conditions. The 2026
   `utilities/FuelSim.java` and `TrenchFuelCollisions.java` show the *behavior* we want (intake
   detection, shot trajectories, logging to AdvantageScope), but they **are built on maple-sim's
   arena classes**, so the logic would need to be ported, not copied.
4. **Collisions with field walls (optional):** clamp the simulated pose to the field boundary in
   code if autos need it.

:::{admonition} Re-check each season
:class: info
If maple-sim publishes a stable release for the current season, it's worth trying again. It
adds realistic collisions and wheel slip that CTRE's sim doesn't model. Keep it behind
the IO layer (only in a `DriveIOSim`/`GyroIOSim` implementation) so swapping it in or out never
touches robot logic. Check [maple-sim's releases](https://github.com/Shenzhen-Robotics-Alliance/maple-sim/releases)
after kickoff.
:::

## Simulation rules

- **Every subsystem has a sim IO.** A PR adding a new mechanism without one isn't done.
- **Sim uses the same constants as real** (gear ratios, limits, gains), so sim results mean
  something.
- **Sim-only code stays in sim IO classes** or behind `RobotBase.isSimulation()`. It never lives in
  subsystem logic.
- **Keep it simple.** A sim that's 80% right and always works beats a perfect one nobody can
  maintain.

## 2027 changes

- The strategy doesn't change: WPILib physics sims plus Phoenix 6 simulation, behind the IO layer.
- WPILib 2027 adds **simulation of SystemCore's built-in IMU**.
- Simulating with the real 2027 Driver Station is planned for a later release; use the Sim GUI's
  robot-state controls for now.
- No 2027 release of maple-sim was found as of November 2026, which supports the decision above.
