# CTRE Swerve

Starting in 2027 we use **CTRE's swerve library** (part of Phoenix 6) with code generated by
Phoenix Tuner X, and we no longer use YAGSL. This page explains how swerve works and how to set it up.

## How swerve works

Each of the four **modules** has a **drive** motor (wheel speed) and a **steer** motor (wheel
angle), plus a CANcoder for absolute steer angle. Because every wheel can point anywhere, the robot
can translate in any direction while rotating.

```text
Driver input ──▶ ChassisSpeeds (vx, vy, ω)
                     │  inverse kinematics
                     ▼
            4 × SwerveModuleState (speed, angle)
                     │  each module: steer PID + drive velocity control
                     ▼
              motors ──▶ encoders + gyro
                     │  forward kinematics + odometry
                     ▼
                  Pose2d estimate
```

| Concept | Meaning |
|---|---|
| `ChassisSpeeds` | Desired robot velocity: vx, vy (m/s), ω (rad/s) |
| **Robot-relative** | +X is the robot's front |
| **Field-relative** | +X is downfield, whichever way the robot faces. What drivers want. |
| `SwerveModuleState` | One module's wheel speed and angle |
| **Kinematics** | Converts between chassis speeds and module states |
| **Odometry** | Integrates wheel movement and gyro heading into a pose |
| **Module optimization** | Steer no more than 90° by reversing the wheel instead |

## Generating the project with Tuner X

CTRE's **Swerve Project Generator** in Tuner X walks you through the drivetrain: it identifies each
module's motors and CANcoder, checks directions, measures CANcoder offsets, and generates a
`TunerConstants.java` file with every ID, offset, gear ratio, and gain.

:::{admonition} All-CTRE drivetrain required
:class: warning
The generator requires a drivetrain that is all CTRE: 8 TalonFX, 4 CANcoders, and a Pigeon 2.
That's our plan going forward.
:::

Steps (follow the [CTRE swerve docs](https://v6.docs.ctr-electronics.com/en/stable/docs/tuner/tuner-swerve/index.html) ([offline](../../reference-materials/offline/ctre-reference.md#swerve-project-generator))
for screenshots):

1. Update firmware on every drivetrain device and put them all on the CANivore.
2. In Tuner X, open **Mechanisms → Swerve Project Generator**.
3. Enter the module type (gear ratios, wheel radius), and assign the devices of each module.
4. Follow the prompts to verify drive and steer directions and to zero CANcoder offsets with all
   wheels pointing forward (bevel gears all facing the same side).
5. Generate. Copy the generated `TunerConstants.java` into our project.

## Using it with AdvantageKit

The generated CTRE project runs its odometry thread on its own and doesn't follow the IO pattern,
so it can't be replayed. To get logging and replay, use the
[AdvantageKit TalonFX(S) Swerve Template](https://docs.advantagekit.org/getting-started/template-projects/talonfx-swerve-template/) ([offline](../../reference-materials/offline/advantagekit-reference.md#talonfx-swerve-template)):

- It uses the **same `TunerConstants.java`** generated by Tuner X.
- It splits the drive into `Drive` (logic), `Module`, `ModuleIO` (`ModuleIOTalonFX`,
  `ModuleIOSim`), and `GyroIO` (`GyroIOPigeon2`). The same pattern you've already learned.
- It runs a high-frequency odometry thread (250 Hz on CAN FD) and replays deterministically.
- It includes drivetrain SysId and wheel-radius characterization commands.

**Recommended setup:** start each season from the AdvantageKit TalonFX swerve template, drop in
that season's generated `TunerConstants.java`, and add our subsystems.

## Driving

```java
drive.setDefaultCommand(
    DriveCommands.joystickDrive(
        drive,
        () -> -driver.getLeftY(),   // forward
        () -> -driver.getLeftX(),   // left
        () -> -driver.getRightX())); // counterclockwise
driver.start().onTrue(Commands.runOnce(drive::zeroHeading, drive).ignoringDisable(true));
```

Things to understand in the drive command:

- **Deadband** the sticks, then **square** the magnitude for finer control at low speed.
- Convert to field-relative using the robot's heading, and **flip for the red alliance**.
- Scale to max speed (from `TunerConstants`).

## Tuning swerve

1. **Steer:** position PID on the steer motor. Tune kP until the wheels snap to angle without
   oscillation. The template's default gains usually work.
2. **Drive:** velocity control. Run drive SysId for kS and kV, then a small kP.
3. **Wheel radius:** run the wheel-radius characterization (spin in place, compare gyro to
   wheel distance). A wrong wheel radius makes odometry drift.
4. **Max speed:** measure it. Don't trust the spec sheet.
